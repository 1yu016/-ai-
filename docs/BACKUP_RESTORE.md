# 备份与恢复

## 备份

1. 暂停写入或使用 SQLite 在线备份机制取得一致快照。
2. 备份 `DATABASE_PATH` 指向的 SQLite 文件。
3. 同步备份 `RESOURCE_UPLOAD_ROOT_PATH`，保持文件路径结构不变。
4. 对数据库和上传目录分别记录时间、大小和校验值。
5. 将备份存放到访问受控且加密的位置。

## 恢复演练

```bash
cd backend
BACKUP_SOURCE=/absolute/path/app.sqlite npm run backup:verify
```

## 正式升级顺序

1. 结束或中止所有进行中课堂，停止后端服务。
2. 复制 SQLite 文件以及资源、数字人、作品上传目录。
3. 对 SQLite 副本执行 `npm run backup:verify`。
4. 在副本环境以 `DB_SYNCHRONIZE=false`、`DB_MIGRATIONS_RUN=true` 启动新版本，完成 001～023 迁移演练。
5. 核对教师、班级、资源、教案、课堂、考勤、奖励、作品、手机会话和审计表数量。
6. 演练通过后再升级正式库。迁移文件的 `down()` 可能删除表，生产环境不能把回滚当作普通恢复手段。

## 恢复后核查

- `PRAGMA integrity_check` 返回 `ok`。
- 管理员看板数量合理，存储目录可读。
- 教师班级隔离、资源权限和课堂恢复正常。
- 上传文件与数据库引用一致。
- 手机控制会话需要重新鉴权，旧短期凭证不能继续使用。
- 审计日志仍为只读且敏感字段已脱敏。

校验脚本把数据库复制到系统临时目录，以只读方式执行 `PRAGMA integrity_check` 并检查核心表，随后删除临时副本。正式恢复时应在停机状态下恢复数据库和上传目录，启动后检查登录、资源读取、教案和课堂记录。不要在运行中的生产数据库上直接覆盖文件。
