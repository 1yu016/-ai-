# 成员 B 阶段五计划书：可更换的 3D 数字人

## 1. 阶段定位

本阶段在第四阶段稳定课堂大屏的基础上，接入可更换的 3D 数字人。数字人负责课堂陪伴、动作反馈和语音播放时的视觉表现，不接管课堂状态机，也不直接执行未经教师确认的 AI 内容。

本阶段优先完成一个可稳定运行的卡通角色和完整降级链路，再扩展角色库、服装、声音和性格配置。

## 2. 阶段目标

- 建立独立的 3D 数字人渲染组件。
- 支持 GLB、glTF 或 VRM 中确定的一种模型格式。
- 加载一个可用于课堂的卡通角色。
- 支持待机、倾听、思考、说话、鼓励、表扬、挥手和再见动作。
- 点击数字人或麦克风按钮进入倾听状态。
- 语音播放时切换说话动作和基础口型，播放结束恢复待机。
- 支持教师选择默认角色和课堂临时角色。
- 播放 PPT、视频或其他资源时可以缩小、移动或隐藏数字人。
- 模型加载失败、WebGL 不可用或性能不足时自动切换到 2D 备用形象。
- 退出课堂时释放模型、纹理、动画和音频资源。

## 3. 阶段边界

本阶段包含：

- 课堂大屏数字人展示。
- 角色选择和角色配置读取。
- 动作状态管理。
- 基础口型和语音播放联动。
- 2D 备用形象。
- 大屏资源展示时的布局切换。

本阶段暂不包含：

- 幼儿参与角色建模。
- AI 自动生成 3D 模型。
- 复杂面部捕捉和全身动作捕捉。
- 手机端实时操控数字人动作。
- 数字人自主决定课堂步骤。

## 4. 页面和组件

### 4.1 数字人渲染组件

建议文件：`frontend/src/components/avatar/DigitalHumanStage.vue`

职责：

- 创建和销毁 WebGL 场景。
- 加载角色模型。
- 播放动作动画。
- 响应尺寸、位置、缩放和显示状态。
- 暴露加载中、已加载、失败和降级状态。
- 在组件卸载时释放所有资源。

### 4.2 数字人控制状态

建议文件：`frontend/src/stores/digitalHuman.ts`

状态包括：

- 当前角色 ID。
- 当前动作：`idle`、`listen`、`thinking`、`talk`、`happy`、`question`、`encourage`、`praise`、`wave`、`goodbye`。
- 是否显示。
- 是否缩小到资源角落。
- 当前模型加载状态。
- 当前语音播放状态。
- 当前降级原因。

动作状态只能由白名单动作驱动，前端不执行后端或 AI 返回的任意脚本。

### 4.3 角色选择面板

建议文件：`frontend/src/components/avatar/AvatarSelector.vue`

第一版展示：

- 角色预览图。
- 角色名称。
- 角色状态。
- 默认角色标识。
- 可用声音和语速配置。
- 选择、预览和恢复默认角色。

如果角色库接口尚未就绪，先使用本地只读角色配置，并在适配层保留接口位置，不虚构后端字段。

## 5. 动作和语音联动

### 5.1 动作规则

| 场景 | 动作 |
| --- | --- |
| 无操作 | `idle` |
| 点击数字人或麦克风 | `listen` |
| AI 生成内容 | `thinking` |
| 数字人播放语音 | `talk` |
| 正向反馈 | `encourage` 或 `praise` |
| 提问 | `question` |
| 课堂开始 | `wave` |
| 课堂结束 | `goodbye` |

### 5.2 语音播放流程

```text
开始播放 → talk + 基础口型
播放中断 → 立即停止动作和音频
播放结束 → 恢复 idle
播放失败 → 显示提示并恢复 idle
```

语音播放必须支持教师立即停止。音频失败不能阻塞课堂步骤切换。

## 6. 课堂大屏布局

- 默认数字人占据右下或右侧区域。
- 课堂步骤和资源仍是主内容。
- 图片、PPT、绘本和视频播放时，数字人自动缩小到角落。
- 教师可以隐藏、显示、移动和缩放数字人。
- 数字人不能遮挡课堂主要文字和资源控制区域。
- 资源播放结束后恢复默认尺寸和位置。
- 小屏或低分辨率设备使用更简单的 2D 布局。

## 7. 模型加载和降级策略

### 7.1 加载流程

1. 检测浏览器 WebGL 能力。
2. 读取当前角色配置。
3. 加载模型和纹理。
4. 加载动作片段。
5. 显示首帧并进入 `idle`。
6. 记录加载耗时和失败原因。

### 7.2 降级条件

以下任一情况发生时切换 2D 备用形象：

- WebGL 不可用。
- 模型地址失效。
- 模型解析失败。
- 纹理加载失败。
- 加载超时。
- 连续帧率低于设定阈值。
- 设备内存或显卡能力不足。

降级后必须保留课堂步骤、资源播放、教师控制和语音功能。

## 8. 后端接口依赖

优先使用成员 A 已提供或确认的角色接口。前端适配层只声明实际存在的字段：

- 角色列表。
- 角色详情。
- 默认角色读取。
- 角色启用或停用状态。
- 模型地址、预览图、动作配置和声音配置。

如果角色库接口尚未提供，第一版使用本地配置完成渲染组件和动作状态机，待接口确认后再接入，不自行推测接口路径或响应结构。

课堂运行接口仍由第四阶段的 `/classroom-runs/*` 负责。数字人不能修改课堂运行状态。

## 9. 实现顺序

### 第 1 步：技术选型和资源确认

- 确认使用 Three.js、Babylon.js 或项目现有渲染依赖。
- 确认模型格式、授权、文件大小和动作命名。
- 确认模型文件的部署路径和缓存策略。
- 确认至少一个可用的 2D 备用形象。

### 第 2 步：渲染组件

- 完成场景、相机、灯光和模型加载。
- 完成加载中、成功、失败和卸载状态。
- 完成资源释放和重复加载保护。

### 第 3 步：动作状态机

- 完成十种标准动作映射。
- 完成动作切换和当前动作去重。
- 完成动作缺失时回退到 `idle`。

### 第 4 步：语音联动

- 接入现有 TTS 播放流程。
- 播放开始切换 `talk`。
- 播放停止、结束和失败恢复 `idle`。
- 增加基础口型，不追求复杂面部捕捉。

### 第 5 步：课堂布局接入

- 接入第四阶段课堂大屏。
- 完成资源播放时缩小和恢复。
- 完成隐藏、移动和缩放。
- 完成 2D 降级形象切换。

### 第 6 步：角色选择

- 接入角色配置适配层。
- 支持默认角色和临时角色。
- 接入角色选择面板。

## 10. 验收标准

- 大屏课堂能稳定显示一个 3D 卡通角色。
- 模型加载失败时 2D 备用形象自动出现。
- 课堂步骤和资源播放不依赖 3D 模型成功。
- 点击数字人或麦克风后进入倾听状态。
- TTS 播放期间显示说话动作，停止后恢复待机。
- 能够播放待机、倾听、思考、说话、鼓励、表扬、挥手和再见动作。
- PPT、视频或绘本展示时数字人不会遮挡主要内容。
- 退出课堂后 WebGL、模型、纹理、动画和音频资源被释放。
- 连续运行一节完整课堂没有明显内存增长或页面卡死。

## 11. 测试计划

### 单元测试

- 动作白名单和未知动作回退。
- 动作切换状态机。
- 语音开始、结束、停止和失败状态。
- 模型加载失败进入降级状态。
- 重复加载和卸载不会残留资源。

### 组件测试

- 加载中、成功、失败和 2D 降级展示。
- 隐藏、显示、移动和缩放。
- 资源播放时数字人缩小。
- 数字人播放语音时动作切换。

### 浏览器测试

- 真实浏览器加载模型。
- WebGL 不可用时显示备用形象。
- 课堂刷新后数字人恢复正确状态。
- 退出课堂后重新进入，旧模型不会叠加。
- 连续切换步骤和资源时页面不崩溃。

## 12. 审查门禁

每个子功能完成后检查：

1. 模型和音频资源来源明确，授权和部署路径可追溯。
2. 不执行任意 AI 返回脚本、URL 或未经确认的动作指令。
3. 课堂运行状态仍由 `/classroom-runs/*` 管理。
4. 3D 失败不会影响步骤、资源和结束课堂。
5. 类型检查、组件测试和浏览器测试通过。
6. 检查卸载后的 WebGL、事件监听器、音频和 Blob 资源是否释放。
