# 成员 B 阶段四计划书：课堂运行与大屏闭环

## 1. 阶段定位

本阶段完成“备课完成后如何安全、连续地上一节课”的前端闭环：上课前检查、进入课堂、步骤推进、资源播放、暂停恢复、结束课堂和刷新恢复。

本阶段不实现 3D 数字人建模、不扩展 AI 课堂导演、不实现自动人脸考勤、奖励系统和手机实时遥控。这些功能分别放在后续阶段，避免课堂主流程与未完成能力耦合。

## 2. 阶段目标

- 教师从教案列表进入上课前检查页。
- 检查大屏、麦克风、扬声器、网络、AI 服务、3D 模型和课程资源状态。
- 通过检查后进入独立的大屏课堂页面。
- 课堂页只展示幼儿当前需要看到的内容，隐藏后台菜单、编辑入口和敏感信息。
- 显示课堂主题、当前步骤、教学内容、教师提示和预期回答。
- 支持上一步、下一步、重复本环节、暂停、恢复、完成和中止。
- 暂停时禁止推进步骤；已结束课堂禁止继续操作。
- 刷新页面后恢复当前课堂状态。
- 浏览器返回和关闭页面时保护正在进行的课堂。
- 单个资源加载失败时显示局部错误，不让整个课堂崩溃。

## 3. 页面与路由

### 3.1 上课前检查页

建议路由：`/classroom/lesson/:runId/check`

页面内容：

- 当前教案名称、班级和教室信息。
- 设备检查卡片：大屏、麦克风、扬声器、网络。
- 服务检查卡片：AI 服务、3D 模型、课堂资源。
- 检查状态：检查中、正常、异常、未检查。
- 单项重试和全部重试。
- “进入课堂”按钮仅在必要检查通过后可用。
- 设备或服务不可用时给出中文原因和降级提示。

### 3.2 独立课堂大屏页

建议路由：`/screen/classroom/:runId`

页面布局：

- 顶部：课程主题、班级名称、当前状态和已用时间。
- 中部：当前步骤内容、资源播放区域、数字人占位区域。
- 辅助区域：教师提示、预期回答、当前步骤剩余时间。
- 底部：上一步、重复、暂停/恢复、下一步、结束课堂。
- 资源错误只占用资源区域，保留步骤控制和结束操作。

大屏模式要求：

- 不显示管理端菜单、编辑按钮、教师账号信息和敏感数据。
- 默认全屏或沉浸式展示。
- 控制栏支持鼠标、触摸和键盘基本操作。
- 数字人区域先使用现有占位组件，后续阶段替换为 3D 组件。

### 3.3 结束确认

- 完成课堂和中止课堂都必须二次确认。
- 完成后进入课堂结果页或返回教案列表。
- 中止后保留已产生的课堂记录，不能删除教案和资源。
- 已完成、已中止状态只读，禁止继续切换步骤或播放控制。

## 4. 前端状态设计

沿用现有 `lessonRun` store，补齐以下状态：

- `run`：课堂运行数据。
- `status`：`running / paused / completed / cancelled`。
- `currentStep`：当前步骤。
- `elapsedSeconds`：课堂已用时。
- `stepElapsedSeconds`：当前步骤实际用时。
- `resourceState`：资源加载中、成功、失败和不支持。
- `checkState`：上课前检查结果。
- `isTransitioning`：防止重复点击产生并发请求。

状态转换必须集中处理：

```text
未开始 → 进行中 → 暂停 → 恢复进行 → 已完成
                         ↘ 已中止
```

前端不自行伪造课堂状态。每次推进、暂停、恢复和结束后，以后端响应覆盖本地状态。

## 5. 后端接口使用范围

优先使用阶段三已经存在的接口：

- `POST /lesson-plans/:id/start`
- `GET /lesson-runs/:id`
- `PATCH /lesson-runs/:id/progress`
- `POST /lesson-runs/:id/pause`
- `POST /lesson-runs/:id/resume`
- `POST /lesson-runs/:id/complete`
- `POST /lesson-runs/:id/cancel`

资源播放沿用阶段二已验证的受保护下载接口，由前端资源播放器处理 Blob 和播放错误。

上课前检查如果后端没有统一检查接口，第一版只做前端可验证项目和已有资源请求检查，并把 AI、3D 模型等标记为“未接入/可降级”。不在前端擅自声明新的后端接口；需要后端支持时先登记接口需求，由成员 A 确认契约。

## 6. 组件拆分

- `ClassroomPreflightView.vue`：上课前检查页。
- `ClassroomCheckCard.vue`：单项检查卡片。
- `ClassroomScreenView.vue`：独立大屏容器。
- `ClassroomStepPanel.vue`：步骤内容和教师提示。
- `ClassroomResourceStage.vue`：图片、音频、视频、PDF、PPT 的资源展示。
- `ClassroomControls.vue`：步骤和课堂状态控制。
- `ClassroomExitConfirm.vue`：完成、中止和离开保护。
- `stores/lessonRun.ts`：课堂状态与接口动作集中管理。

现有 `LessonClassroomView.vue` 可以逐步拆分，先保证功能和状态正确，再做视觉细化。

## 7. 实现顺序

### 第 1 步：契约和状态审查

- 对照后端 DTO、响应字段和状态枚举。
- 确认课堂运行接口的错误码和并发版本规则。
- 检查资源响应是否能支持课堂播放。
- 为缺失契约建立待确认清单，不直接猜接口。

### 第 2 步：课堂运行状态

- 修正 `lessonRun` 类型和接口路径。
- 完成加载、推进、暂停、恢复、完成、中止。
- 增加重复点击保护和已结束只读保护。
- 增加刷新恢复和课堂离开保护。

### 第 3 步：上课前检查页

- 建立检查卡片和状态展示。
- 接入已有资源和课堂请求检查。
- 增加重试、降级和进入课堂条件。

### 第 4 步：大屏课堂页

- 完成沉浸式布局和步骤展示。
- 接入资源播放器。
- 处理资源加载失败、切换步骤和重复播放。
- 隐藏管理端信息和编辑入口。

### 第 5 步：验收和回归

- 使用真实后端完成一节完整课堂。
- 验证刷新、暂停、恢复、结束和异常资源场景。
- 检查阶段一、二、三路由和资源库不受影响。

## 8. 验收标准

- 教师可从教案列表进入上课前检查页。
- 检查通过后可进入独立大屏课堂页。
- 课堂页能够正确显示当前步骤及资源。
- 上一步、下一步、重复、暂停、恢复均与后端状态一致。
- 暂停时不能进入下一步。
- 完成和中止必须二次确认。
- 页面刷新后课堂状态、当前步骤和控制权限不丢失。
- 已结束课堂不能继续操作。
- 浏览器返回会提示课堂未结束。
- 单个图片、音频、视频、PDF 或 PPT 加载失败时，页面仍可继续结束课堂。
- 大屏页面不暴露后台菜单、编辑功能和敏感信息。

## 9. 测试计划

### 单元测试

- 课堂状态转换。
- 暂停状态禁止推进。
- 已结束状态禁止所有课堂操作。
- 重复点击只产生一次请求。
- 后端错误信息能够转成中文提示。

### 组件测试

- 上课前检查状态和重试。
- 步骤内容、教师提示和预期回答展示。
- 资源加载成功、失败和不支持类型展示。
- 完成/中止二次确认。

### 端到端测试

- 登录 → 教案列表 → 上课前检查 → 进入课堂。
- 下一步 → 暂停 → 恢复 → 重复本环节 → 完成课堂。
- 刷新课堂页后恢复课堂。
- 中止课堂后无法继续推进。
- 资源加载失败后仍可结束课堂。

## 10. 阶段边界和风险

- 3D 数字人只保留稳定占位，不在本阶段引入模型加载和口型同步。
- 手机实时遥控放到后续协同阶段；本阶段先保证大屏本地操作完整。
- 自动考勤、奖励、课间模式和 AI 课堂导演不放入本阶段验收。
- PDF/PPT 是否能直接浏览取决于浏览器和后端资源格式；不支持时必须提供下载或明确提示。
- 真实端到端测试需要后端服务、数据库、登录账号和可播放资源，不能只用前端 Mock 代替。

## 11. 审查门禁

每完成一个子功能，执行以下检查：

1. 前端路径、请求方法、请求体和响应字段与后端代码逐项对照。
2. 不新增未经成员 A 确认的接口。
3. 类型检查和相关单元测试通过。
4. 真实后端下至少走通一次课堂状态转换。
5. 阶段一、阶段二和阶段三已有页面回归通过。
